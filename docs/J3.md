# J3 — Sécuriser et fiabiliser le système IoT

## Questions à résoudre

### Comment distinguer sans ambiguïté plusieurs capteurs simulés qui publient en parallèle ?

Chaque capteur possède un `device_id` stable et unique déclaré dans
`infra/kit/devices.json`. Cette identité apparaît à tous les niveaux :

- client MQTT : `campus-{device_id}` ;
- topic : `campus/v1/devices/{device_id}/telemetry` ;
- corps JSON : champ `device_id` ;
- événement : `message_id` unique, exposé comme `eventId` dans les logs ;
- MongoDB : `device_id` extrait du topic avec le message brut ;
- PostgreSQL : `device_id` dans l'historique et clé primaire de `device_state` ;
- API : chaque salle contient explicitement ses devices ;
- logs : champs `deviceId`, `eventId` et `topic`.

Le simulateur refuse de démarrer si deux entrées de `devices.json` possèdent le
même `device_id`. Le backend s'abonne avec le joker MQTT `+`, extrait l'identité
du topic, puis vérifie qu'elle correspond à celle du corps. Une différence est
traitée comme une tentative d'usurpation : le brut reste disponible pour audit,
mais le message n'atteint pas PostgreSQL et ne modifie aucun état courant.

## Reproduire la preuve d'isolation

Observer deux cycles complets de publication :

```sh
docker compose --profile tools run --rm tools watch --topic "campus/v1/devices/+/telemetry" --count 6
curl http://localhost:3000/rooms
docker compose exec -T postgres psql -U campus -d campus -c "SELECT device_id, count(*) FROM telemetry GROUP BY device_id ORDER BY device_id;"
```

Dans Grafana, ouvrir **Campus connecté - Logs**, panneau
**Télémétries traitées par capteur**. La requête utilisée est :

```logql
sum by (deviceId) (
  count_over_time(
    {service_name="backend"}
      | json
      | eventType="mqtt.telemetry.processed"
      | deviceId=~"$device_id"
    [$__auto]
  )
)
```

Pour suivre une seule mesure, saisir son `message_id` dans la recherche Grafana.
Les logs `mqtt.message.received` puis `mqtt.telemetry.processed` partagent le
même `eventId`.

## Fonctionne

- Trois capteurs publient en parallèle avec des identités stables et uniques.
- Les topics, le stockage, l'API et les logs conservent cette séparation.
- Une incohérence entre l'identité du topic et celle du corps est rejetée pour
  la télémétrie, l'état et la disponibilité.
- Grafana permet de filtrer par `deviceId` et de suivre un `eventId`.

## Limites ou dette connue

Le compte MQTT `simulator` est partagé par les trois objets du kit. Le backend
détecte donc une usurpation dans les données, mais le broker n'authentifie pas
encore chaque capteur avec des identifiants MQTT distincts.
